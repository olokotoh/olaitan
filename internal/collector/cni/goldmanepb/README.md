# goldmanepb

Vendored Calico Goldmane protobuf stubs. The Goldmane gRPC API is
the flow-export mechanism Story 1.3 selected (ADR-2026-04-30-01)
and the substrate Story 1.10's `internal/collector/cni/` adapter
consumes.

The SHA pin is content-addressed and survives an upstream tag yank.

## Regeneration

`buf` 1.55+ plus the `protoc-gen-go` and `protoc-gen-go-grpc`
plugins must be on `PATH`. From this directory:

```bash
buf generate
```

The `buf.gen.yaml` writes both `api.pb.go` and `api_grpc.pb.go`
back into this directory with `paths=source_relative`. The
generated files carry `// Code generated by protoc-gen-go. DO NOT
EDIT.` headers and **must not** be hand-edited; if the contract
needs to change, edit `api.proto` and regenerate.

## Why vendored and not `buf.build/projectcalico/goldmane`

Calico had not published the Goldmane proto to the Buf Schema
Registry as of v3.31.5. When upstream publishes, an Epic 6
hardening story can switch from the vendored copy to a `buf push`
dependency. Until then this vendored stub is the pin.

## Convention

The directory layout mirrors `internal/collector/falco/falcopb/`:
each adapter under `internal/collector/<source>/` owns its
vendored proto stubs in a `<source>pb/` sub-directory. Story
1.10 lifts the same convention; future stories that vendor proto
should follow it.
